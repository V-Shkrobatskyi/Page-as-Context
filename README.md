# Page as Context

Give AI assistants structured web page context with **Page as Context**, a Chrome and Firefox browser extension. Copy pages as compact Semantic Text or Markdown, or connect AI agents through the **Model Context Protocol (MCP)** to read shared tabs and perform supported actions. Capture and filtering run locally without an LLM API, developer capture backend or analytics.

## Install for Chrome and Firefox

Install from the [Chrome Web Store](https://chromewebstore.google.com/detail/page-as-context/ghkjolcdeccimnjhdebaklffpekfmojd) or [Firefox Add-ons](https://addons.mozilla.org/en-US/firefox/addon/page-as-context/).

| Browser | Capture method | Export | Minimum version |
| --- | --- | --- | --- |
| Chrome Desktop | Accessibility-tree snapshot | Preview, Copy and Save | Chrome 125+ |
| Firefox Desktop | HTML/ARIA semantics | Preview, Copy and Save | Firefox 140 |
| Firefox Android | HTML/ARIA semantics | Preview and Copy; no Save | Firefox Android 142 |

These are manifest minimums; platform verification details are in the [Firefox Desktop](docs/firefox-desktop-testing.md) and [Android](docs/firefox-android-testing.md) guides. The same Firefox add-on supports Desktop and Android. Desktop Firefox requests optional download permission when saving.

MCP is desktop-only. The supplied native AI-app packages target **macOS Apple silicon**; check each package guide for app requirements. Windows users can use Local HTTP, with Windows 10 x64 Chrome/Firefox reads and actions user-verified. Linux HTTP startup still needs live acceptance. Windows native packages, incognito, additional browser profiles and VS Code/Cursor plugins are not current support promises.

For local extension installation and reproducible packages, follow [BUILDING.md](BUILDING.md). Installing the browser extension is sufficient for ordinary capture and export.
Package filename examples in the app guides refer to current source builds.

## Turn web pages into AI context

1. Open an ordinary web page, then open Page as Context from the browser toolbar or Android extensions menu.
2. Keep the default **Compact** compression and **Redact sensitive data**, or choose Semantic Text/Markdown and your preferred settings. Filters do not need configuring before your first Copy.
3. Click **Copy context** and paste into a conversation or notes. Ask a specific question about the exported page. On Desktop, **Save to file** creates a local UTF-8 file.
4. For review, choose **Preview & edit**, change the prepared text, then Copy or Save from the editor. Keep the popup open until the editor is ready; drafts stay in memory and disappear when that tab closes or reloads.

Example clipboard export using **Compact Semantic Text** with credential redaction enabled. The page, browser version, timestamp and extension version below are illustrative metadata:

```text
<web_page>
Page: Project overview
URL: https://example.test/
Browser: Firefox Desktop 160.0
Captured: 2026.11.12 12:00:00
Generated by browser extension "Page as Context" 2.2.7/5/d (created by V. Shkrobatskyi)

page
  heading "Project overview" [level=1]
  button "Create project" [disabled=false]
</web_page>
```

The export includes semantic structure and control states. Paste it into an LLM chat with your question, such as: "What can I do on this page, and where can I change the project settings?"

Real exports also include page metadata according to your data controls. Copy adds context boundaries; Save writes text without them. **Remember settings** keeps your export choices for the next popup session. Keep temporary save tabs open until saving finishes; successful saves close them automatically.

On Desktop, **Select element** lets you choose one block, adjust the selection and Preview, Copy or Save it. [Whole-page keyboard shortcuts](docs/capture-and-export.md#desktop-keyboard-shortcuts) are available through **Shortcuts** in the popup footer. See [capture and export](docs/capture-and-export.md#preview-and-edit-before-copying) for the picker, editor lifecycle and shortcut assignments.

## Connect AI apps and agents with MCP

Connect ChatGPT, Claude or another compatible AI client. Choose one route; both use the extension's privacy controls, organization policies and explicit tab grants. Copy and export also work without MCP.

| Route | Use it when | Start here |
| --- | --- | --- |
| Native app plugin | You use a supplied macOS Apple silicon package; it bundles the helper/runtime and starts the bridge | [Native setup and pairing](docs/mcp-integration.md) |
| Local HTTP (HFS) | Cross-platform route for **macOS, Windows and Linux** clients with Streamable HTTP MCP and Authorization headers; keep HFS running. Linux startup remains unverified | [HTTP setup](docs/hfs-integration.md) and [first-use launchers](docs/hfs-launchers.md) |

Native package installation guides: [ChatGPT desktop](integrations/chatgpt/PACKAGE-README.md), [Claude Desktop / Claude Code](integrations/claude/PACKAGE-README.md), [Antigravity](integrations/antigravity/PACKAGE-README.md), and [GitHub Copilot app](integrations/github-copilot-app/PACKAGE-README.md). Current package sources are **1.2.7**, independently versioned from the extension and helper. Their guides distinguish current installation examples from earlier live verification. Copilot's Chrome core flow was user-verified; Firefox live testing for that package was skipped.

Native setup does not require HFS or a duplicate manual server. HTTP clients must run on the same computer as HFS; cloud-hosted and stdio-only clients cannot connect directly. For local models, connect an MCP-capable app to your model runtime; tool-calling support alone is insufficient. The HTTP guide records the narrower Goose/Ollama read test and its limits.

MCP starts **disabled**. Pairing a native client or authorizing an HTTP key grants no tab access: explicitly choose **AI: Read** or **AI: Write** on each intended tab. Write also needs **Read and write** mode and asks before each action by default. Connection-scoped approval can skip later prompts until navigation, expiry or disconnection, unless organization policy requires every approval.

**Automatic access follows the shared tab across reloads and site changes.** New tabs start Off; the default inactivity timeout is one hour. Reconnection can restore validated Read for an existing unexpired sharing choice, never Write or session approvals. Use AI Off, Revoke or Stop all MCP access to end access; these cannot retract data already returned to the AI app.

Both transports offer full-page reads, exact targeted reads and supported single/grouped writes. Targeted reads return bounded context around an exact semantic target or named group; ambiguity and incomplete capture are explicit. Scoped fill responses reduce returned context while still capturing the full permitted page internally. These features do not establish faster capture or a measured advantage over other MCP tools.

Write targets are limited to supported native controls and a narrow class of named, focusable div/span buttons. Arbitrary custom widgets, password/file/payment fields and unsupported editors remain excluded. An **applied** receipt confirms dispatch, not persistence or completion of later asynchronous updates. Inspect an unknown result with a read; never replay a write to refresh context. See the [MCP contract](docs/mcp-development.md#read-interact-test-and-revoke).

## Compact AI context with local privacy controls

- **Structured web context for AI:** capture text, headings, links, controls and exposed states. Preview and selected-block export let you choose what to share.
- **Redact sensitive data before sharing:** built-in credential and personal-data rules, custom literal/field/URL/Regex rules, import/export, Try filters and a synthetic Demo. Save filter edits to apply them to future exports; imported or exported custom terms can themselves be private.
- **Control what AI can see:** exclude titles and form values, reduce URL metadata, restrict capture sources, and review diagnostics. Capture-header history is optional and off by default; captured page contents are not archived by the extension.
- **Managed browser deployment:** administrators can restrict exports, origins, MCP access and data handling. Personal settings cannot weaken organization policy.

| Context compression | Export behavior |
| --- | --- |
| Without | Every captured semantic node, not all HTML |
| Detailed | Removes unnamed wrappers without semantic attributes |
| Compact (default) | Removes repeated accessibility noise, retaining meaningful controls |
| Maximum | Packs Compact output; falls back when packing adds overhead |

Token counts are approximate, not model-specific tokenization. Different compression levels can produce identical output.

Capture/filtering stay on your device, but **your AI client may send returned context to its model provider**. Local processing does not mean a local model. Clipboard text and saved files remain in the destinations you choose. The extension keeps a bounded local technical journal and, if enabled, capture-header history; nothing is sent automatically. Read the [privacy policy](PRIVACY.md).

Redaction is heuristic and cannot guarantee removal of every private value. Password input values are always omitted, even when redaction is off. Review output before sharing it. Page content can contain prompt injection; treat exports as untrusted evidence. Redaction, compression and boundaries do not guarantee removal of malicious instructions.

Capture is not OCR and does not promise the entire DOM, unloaded or unmounted virtualized content, closed shadow roots or canvas pixels. Eligible embedded documents can be included; changing or inaccessible frames yield partial-capture warnings. Browser-internal pages and protected sites may reject capture. Chrome briefly uses the debugger permission and may display a browser warning. Firefox includes same-origin frames by default; **Include frames from other sites** requests persistent access to all HTTP/HTTPS sites, revoked when switched off.

## Build and contribute

Build the extension from source with Node.js **24.10.0** and npm **11.6.0**:

```sh
npm ci
npm run dev
npm run check
```

See [CONTRIBUTING.md](CONTRIBUTING.md) for workflow and checks, [BUILDING.md](BUILDING.md) for both browser builds and packages, and the [release guide](docs/releasing.md) for submission. Shared popup changes require rebuilding and reloading both targets. Native probes are documented in [capture and export](docs/capture-and-export.md#native-browser-probes); see also the [architecture](src/core/README.md) and [changelog](CHANGELOG.md).
