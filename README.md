# Page as Context

Copy a compact, semantic representation of the current page into an AI conversation or local notes. Choose Semantic Text or Markdown, adjust compression, and export with one click. Processing stays on your device: no LLM API, capture backend, or analytics.

## Example export

Example clipboard export using **Compact Semantic Text** with credential redaction enabled. The page, browser version, timestamp and extension version below are illustrative metadata:

```text
<web_page>
Page: Project overview
URL: https://example.test/
Browser: Firefox Desktop 157.0
Captured: 2026.10.05 12:00:00
Generated by browser extension "Page as Context" 2.0.0/5/d (created by V. Shkrobatskyi)

page
  heading "Project overview" [level=1]
  button "Create project" [disabled=false]
</web_page>
```

The export includes semantic structure and control states. Paste it into an LLM chat with your question, such as: "What can I do on this page, and where can I change the project settings?"

## Installation

Install Page as Context from your browser's extension store:

- **Chrome Desktop:** [Chrome Web Store](https://chromewebstore.google.com/detail/copy-as-context/ghkjolcdeccimnjhdebaklffpekfmojd).
- **Firefox Desktop and Android:** [Firefox Add-ons](https://addons.mozilla.org/firefox/addon/copy-as-context/).

### Local development installation

For local installation, use Node.js 24.10.0 and npm 11.6.0:

```sh
npm ci
npm run build
npm run build:firefox
```

- **Chrome:** open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select `.output/chrome-mv3`.
- **Firefox Desktop:** open `about:debugging#/runtime/this-firefox`, choose **Load Temporary Add-on**, and select `.output/firefox-mv3/manifest.json`. Temporary installation ends when Firefox closes.
- **Firefox Android:** use `.output/firefox-mv3` with the [device installation instructions](docs/firefox-android-testing.md).

## Quick start

1. Open the page you want to export, then open the extension from the browser toolbar or Android extensions menu.
2. Choose **Semantic Text** or **Markdown**, a compression level, and the privacy setting.
3. Click **Copy page context**, then paste into your conversation or notes. On Desktop, **Save to file** exports a local UTF-8 file. Firefox asks for download permission the first time. Its Save action opens a separate extension tab; keep it open until saving finishes. It closes after success.

**Preview & edit**, first in the action row, opens the prepared context in a separate tab. Edit the text, then choose **Copy** or, on Desktop, **Save to file** to export your changes. The editor shows counts for copying with boundaries, counts for the text/file without boundaries, and the original compression reduction. Keep the popup open until the editor is ready. Drafts stay in memory and are lost when the editor is closed or reloaded. Direct Copy and Save remain available.

The selected-element panel offers **Preview & edit**, **Copy context**, and **Save to file** actions. They export only the selected block. Direct Copy adds the usual boundaries; Save writes the text without boundaries through a temporary extension tab that closes after saving. Firefox requests download permission when needed. The picker closes after successful copying or after the save tab accepts the export. Cancelling the Save As dialog closes the temporary save tab without activating it. If preparation or copying fails, the picker stays available for retry.

On Chrome and Firefox Desktop, **Select element** starts a picker on the page and closes the popup. Point and click to select one block and its contents; **Select parent**, **Back**, and **Pick again** adjust the choice. Keyboard users can focus an element and press **F2** to select it. **Preview & edit** opens the existing editor with the chosen format, compression, and privacy settings. **Esc** or **Cancel** exits. Selection works on ordinary HTTP/HTTPS pages, in the main document only; available embedded documents inside the chosen block follow the existing frame-access rules. The choice is temporary and ends on navigation, disconnect, or after five minutes. Android continues to offer whole-page capture.

On Chrome and Firefox Desktop, keyboard shortcuts run directly from the current page without opening the popup:

| Action | Windows / Linux | macOS |
| --- | --- | --- |
| Preview & edit | `Alt+Shift+P` | `Option+Shift+P` |
| Copy page context | `Alt+Shift+C` | `Option+Shift+C` |
| Save to file | `Alt+Shift+S` | `Option+Shift+S` |
| Select element | `Alt+Shift+E` | `Option+Shift+E` |

Shortcuts use **saved preferences** (or defaults) and current organization policies. Preview, Copy and Save always capture the whole page; export a selected block through the picker panel. Copy keeps the source page focused. The extension icon briefly shows a check mark on success or `!` on failure; hover over it for details. Shortcut Save uses a temporary extension tab that closes after saving; keep it open until completion. Firefox requests download permission when needed. Repeated shortcuts are ignored while another shortcut action is running.

Choose **Shortcuts** in the popup footer to change or remove assignments. Chrome opens `chrome://extensions/shortcuts`; Firefox opens its shortcut manager where supported, otherwise open the tools menu in `about:addons` and choose **Manage Extension Shortcuts**. Browser, operating-system and other extension shortcuts can conflict; check assignments if a key does nothing. Test your preferred keyboard layouts, especially when `Alt+Shift` switches input languages. Shortcut labels are not shown beside the action buttons.

**Customize**, inside **Redact sensitive data**, opens one table of built-in and custom filters. Toggle existing rows or choose **+ Add filter** to add a literal text rule with optional case matching. The Case sensitive checkbox controls letter case for both built-in and custom filters. **Export** immediately downloads all filters, including built-in definitions and on/off states. **Import** opens a file picker and loads the selected file into the table. Choose **Save filters** to apply imported or edited rows to future exports. The collapsible Try filters section supports Test all, Test selected (including off rules), independent matched-rule diagnostics and synthetic examples/near misses based on the chosen type. Settings stay local; exported files include your custom text.

Email masking (including domains) is enabled by default; full email hiding is available but off. Full hiding overrides masking regardless of row order. Email types need no matching text or case setting. Each row has one **Rule type**. Custom rules offer Text, Text — single literal, Field labels, Field labels — whole words, URL parameters, Authorization, JWT, Assigned secrets and Regex. Automatic email, phone, card, IBAN and personal-field types are built-in only. Regex rows offer ready-to-use examples for email addresses, GitHub tokens, AWS keys, OpenAI keys and order IDs. Duplicate a configurable built-in to create an equivalent editable custom rule, then disable the original if needed. Literal alternatives use ` / ` (space, slash, space). Text — single literal preserves older whole-phrase rules. Older rules with several modes become separate typed rows; old GitHub, AWS and OpenAI custom types become equivalent Regex expressions. V13 exports include a catalog of available types and their descriptions; implementations remain defined by the extension code.

**Hide payment card numbers** and **Hide IBANs** are on by default and require valid checksums (Luhn and MOD-97 respectively); IBAN also requires a recognized country length. **Mask phone numbers** is on by default, preserving separators and showing `min(3, floor(digit count / 2))` digits. **Hide phone numbers** is off by default and recognizes international `+`/`00` formats or numbers following English Phone/Tel/Mobile/Fax labels. Unlabelled local numbers are not detected. **Hide personal field values (English labels)** is off by default and uses a fixed automatic type to hide values under labels such as Full name, Email, Address, Date of birth, Passport, SSN, Card number and Bank account. It keeps labels visible and does not detect names or addresses in prose. Enable it to hide whole field values, including email fields that would otherwise be partially masked. **Mask personal field values (English labels)** is on by default and needs no matching text or case setting: names and addresses use the email length formula, phones keep formatting, and emails use the existing name/domain masking. Documents, dates of birth, bank details and CVV/CVC are fully hidden. Full hiding overrides either mask. These personal-data detectors use no additional runtime dependencies beyond the shared Regex engine.

The automatic **Mask email addresses (including domains)** type needs no matching text or case setting. It changes `abcdef@example.com` to `abc***@exa****.com`, is enabled by default and remains weaker than full hiding.

**Demo**, beside Import / Export, opens a live page containing examples only for enabled filters. It opens in the same tab and carries your current draft without saving preferences; its results combine all enabled rules. Capturing Demo from the popup uses that same draft, while ordinary pages use saved filters. Customize filters returns in the same tab and restores unsaved edits, including unfinished disabled rows. Temporary navigation state stays in this tab’s session storage, separately from saved extension preferences. Built-in examples are synthetic; custom examples may contain your matching terms. Arbitrary Regex rules without an example are listed with a link to Try filters. Demo captures its own DOM through a packaged script in both browsers; other extension/browser pages stay blocked and no extra permissions are requested.

**Try filters** supports Text or field value, Link URL, Page title and Page URL contexts. Field labels provide context only when testing field values; phone, card, IBAN, email and credential samples otherwise need no additional inputs.

**Save preferences** keeps your compression, format, and privacy choices for the next popup session.

| Compression | Behavior |
| --- | --- |
| Without | Keeps every captured semantic node, rather than all page HTML |
| Detailed | Removes unnamed wrappers without semantic attributes; preserves text, links and states |
| Compact (default) | Removes repeated accessibility noise while retaining meaningful controls |
| Maximum | Packs Compact output with selective abbreviations and repeated structures; falls back when packing would add overhead |

Copy wraps the export in `<web_page>` boundaries, or `**` boundaries for Maximum. Save exports the context without these boundaries. Token counts are rough estimates, not model-specific tokenization.

## Privacy and limitations

[Read the privacy policy](PRIVACY.md). Page content, URL, semantic form values, and browser metadata are processed locally after an export action. The extension sends no captured data to the developer or an LLM service. Only preferences and redaction filter settings are persisted by the extension; copied text and saved files remain in the destinations you choose.

**Redact sensitive data** is enabled by default. Credential redaction is heuristic and cannot guarantee removal of all private information. Both browser builds omit password input values, even with redaction disabled. Review exports before sharing them.

Capture reflects browser accessibility or HTML/ARIA semantics. It does not perform OCR or promise complete page coverage. Firefox includes eligible same-origin embedded documents by default. Enable **Include frames from other sites** to request access to all HTTP/HTTPS websites once and include available cross-origin frames. It skips hidden frames and tracking pixels, keeps document boundaries and reports partial capture. The same option works on Desktop and Android. Access persists across tabs and browser restarts; turning the option off revokes site access. Copy, Preview, and Desktop Save are the capture triggers. Firefox omits closed shadow roots, canvas pixels, and unmounted virtualized content. Browser-internal pages and protected sites may reject capture. Chrome 125+ includes eligible embedded documents in their page positions, including cross-origin frames. Hidden frames and tracking pixels are skipped; visible advertising can still appear. Frames below the viewport can be included. Unavailable or changing frames produce a partial-capture warning. Chrome briefly uses the `debugger` permission and may display a browser warning.

Page text can contain instructions aimed at an AI assistant. Treat exports as untrusted source material and tell the assistant to use them as evidence for your task. Compression, redaction, and export boundaries do not remove all malicious instructions.

See [capture and export details](docs/capture-and-export.md) for browser differences, permissions, metrics, privacy behavior, and troubleshooting.

### Data controls and diagnostics

Use **Data controls** in the popup to exclude document titles, reduce or omit URL metadata, omit current form values, manage the bounded local technical journal, and preview/copy/save a diagnostic JSON report. Nothing is sent automatically. Administrators can restrict capture origins and enforce data exclusions, logging level and retention limits. See the [guide](docs/data-controls-and-diagnostics.md) for behavior and limitations.

Optional capture-header history is off by default, with personal or managed retention of 1–365 days and 1–50 MiB (defaults: 60 days / 10 MiB). It keeps no captured content and has separate viewing, clearing and JSON export in Diagnostics.

Personal site restrictions are available in **Data controls → Capture sources**. Block sites or explicitly enable an allowed list for page, element and embedded-frame captures; personal rules can only strengthen organization restrictions. See [data controls](docs/data-controls-and-diagnostics.md#capture-source-restrictions).

## Optional MCP integration

Connect an external assistant to one explicitly shared tab in Read only or Read and write mode. MCP starts disabled and uses a separately installed local helper. Privacy filters and organization policies apply. Write actions require additional browser-side permission and approval. The client may forward context to its model provider. See [setup, limits and verification](docs/mcp-integration.md).
